- `src/html_text.rs` reviewed with no findings.
- `src/html_writer.rs` reviewed with findings:
  - low: a template dropped or failing part-way leaves its markup open with the writer still usable, so an application that keeps rendering, such as a fallback after a timeout, can have later escaped values parsed as attributes, and a slow client can time the cut (also src/html_body.rs, context/streaming.md, and design/streaming.md); fixed in #2.
  - low: runtime escaping passes U+001B, so a response served without a declared charset could be sniffed as ISO-2022-JP and shift escaped values out of their context; accepted, documents must be served as UTF-8 as design/rendering.md requires (`// SECURITY:` at `HtmlWriter::write_escaped`).
  - high: a destination reporting more bytes than offered overflows `written`, and one returning `Interrupted` indefinitely spins; rejected, destinations are application-selected `AsyncWrite` implementations and a remote peer cannot make a conforming implementation report either (`// SECURITY:` at `HtmlWriter::drain`).
  - low: the 512-byte `write_display` limit makes rendering fail for a longer formatted value; rejected, the fallback is explicit, built-in primitives format to at most 327 bytes, and strings stream through `HtmlText` (`// SECURITY:` at `HtmlWriter::write_display`).
  - high: the UTF-8 `expect` in `write_display` would panic if the scratch buffer held a partial character; rejected, `FormatBuffer::write_str` copies only whole `&str` chunks and rejects any chunk that does not fit (`// SECURITY:` at `FormatBuffer::write_str`).
  - high: `write_literal` is public and writes a string without escaping; rejected, it accepts only `'static` data the application controls, which untrusted data reaches only through deliberate leaking (`// SECURITY:` at `HtmlWriter::write_literal`).
